# AI-Assisted Learning Workflow

## Core Thesis

AI helps learning when it accelerates the loop around a learner-owned goal: find resources, prime the field, transform formats, clarify gaps, create feedback, and support implementation. It should not replace the learner's work of choosing relevance, organizing relationships, and proving understanding through use.

The source's core loop is:

```text
goal
-> research
-> priming
-> comprehension
-> implementation
```

This page is about using AI inside that loop. It is not mainly about attention training or deep-processing tanking.

## Source Boundary

Primary source:

- **How I Learn Things Really Fast (with AI)** - supplies the five-step learning workflow and the concrete AI use cases.

Supporting sources:

- **Elon Musk - How To Learn Anything** - supplies the problem-first principle: relevance appears when the tool is needed for a real problem.
- **How to Learn ANYTHING Faster Than Everyone** - supplies the guardrail: effort should not be removed when that effort is the learning.

## Compressed Takeaways

1. **Start with the final artifact.** The learner needs a puzzle-box picture: exam, report, app, dashboard, slide deck, essay, workflow, or wiki page.
2. **AI is best at search, transformation, feedback, and artifact support.** These are high-friction activities that do not require giving up the learner's schema.
3. **Priming should be fast and deliberate.** Study guides, quizzes, keywords, examples, and starter artifacts orient the brain before depth work.
4. **Comprehension should be layered.** First pass: definitions, major concepts, full examples. Later passes: detail and integration.
5. **Format conversion can be legitimate acceleration.** Text can become audio, video script, textbook-style notes, diagrams, or tables if the learner still processes the content.
6. **Implementation is part of learning.** The artifact is not just output; it reveals whether the learner can use the knowledge.
7. **AI should not own relevance or organization.** If AI decides what matters too early, the learner may produce better notes while learning less.
8. **Problem-first learning makes tools meaningful.** Teach the screwdriver when the engine requires it.

## Step 1: Goal

The source begins with the goal because the goal determines what counts as useful knowledge.

Weak goals:

- learn AI,
- learn finance,
- get better at coding,
- understand a topic.

Stronger goals:

- build an agent,
- write a report,
- pass a specific exam,
- make a dashboard,
- explain a concept to a defined audience,
- compile a wiki page from sources.

AI can help clarify possible outputs, constraints, and milestones, but the learner must choose the real target.

## Step 2: Research

Research is the missing-pieces phase. The learner often does not have the right resources yet.

Good AI uses:

- search for candidate resources,
- compare courses or documents against the goal,
- collect common learning paths,
- identify prerequisites,
- surface recurring terms,
- and find examples close to the final artifact.

The risk is letting AI rank importance before the learner has any model. At this stage, AI should expand and filter the search space, but the learner should still decide what is worth learning.

## Step 3: Priming

Priming gives the brain a rough structure before deep comprehension.

Good AI uses:

- generate a study guide,
- create preview quizzes,
- extract key terms,
- produce simple definitions,
- identify sections likely to matter,
- summarize starter code or an example artifact,
- and make a first-pass map of the field.

The point is not to know the material yet. The point is to make the material less foreign when the learner enters it.

## Step 4: Comprehension

The source's comprehension strategy is layered. The learner first captures:

- definitions,
- major concepts,
- and full examples.

Then the learner revisits material at greater depth.

Good AI uses:

- convert text into audio or podcast-style script,
- convert video or audio into text,
- make diagrams,
- generate tables,
- explain a specific confusing point,
- provide alternate examples,
- extract the one section the learner needs,
- and clean rough notes into a clearer artifact.

The guardrail from the learning-effort source matters here: if AI removes the thinking that creates learning, the task gets faster but the learning gets delayed. AI can change the medium and make feedback faster. The learner must still compare, organize, retrieve, and explain.

## Step 5: Implementation

Implementation closes the loop. The learner creates the thing the goal required.

Good AI uses:

- outline a report,
- draft a slide deck,
- help code an app,
- generate a dashboard,
- produce practice tasks,
- turn notes into a wiki draft,
- or create a first version of the final artifact.

The implementation step should expose gaps. If the learner cannot explain, modify, defend, or use the artifact, the learning loop is not finished.

## Problem-First Learning

The problem-first source explains why the five-step loop works. The brain discards information that feels irrelevant. A tool taught in isolation feels arbitrary. A tool introduced while solving a problem has an obvious role.

Learning rule:

> Teach tools at the moment of need, not as inventory.

For this wiki, that means AI-learning workflows should begin with the page or capability the user wants to produce. The source pile should serve that output.

## The Operating Model

```text
1. Name the artifact.
   What should exist when the learning is done?

2. Use AI to find resources.
   Gather sources, examples, prerequisites, and paths.

3. Prime the field.
   Generate study guides, preview questions, key terms, and examples.

4. Build the human schema.
   Decide importance, grouping, relationships, and simplifications.

5. Use AI for format and feedback.
   Convert media, explain gaps, diagram, quiz, and clean notes.

6. Implement.
   Produce the report, wiki page, app, dashboard, deck, or workflow.

7. Audit the division of labor.
   Did AI accelerate learning, or did it perform the learning?
```
