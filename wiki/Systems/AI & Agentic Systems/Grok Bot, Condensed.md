# Grok Bot, Condensed

# Grok Bot, Condensed

Grok Bot is a desktop app from SpaceXAI. You create a named bot, write its one standing job in its description, and the bot does the job on a cloud computer that keeps running after your laptop closes. Knowing how the computer, the allowance and the approvals work settles which jobs to give a bot and which to keep off it.

- All bots on an account share one computer and cannot keep secrets apart.
- One job per bot, and SpaceXAI warns against a general helper.
- Standing rules go in the description, and today's task in the chat.
- One weekly allowance covers the account, and every routine run spends some.
- Leave approval on, so a person approves each send or purchase.
- No bot merges code, and a Cursor Cloud Agent opens the pull request.
- On this desk bots only report, and only public material goes on.

## How it works

Every bot on an account runs on the same cloud computer, with the same files, browser and logins. A skill is a saved way of doing a task, and a routine runs a skill or a task on a clock or when an event happens. The order is to do a task in chat, save it as a skill, then put the skill on a routine. Each routine run spends part of the weekly allowance: a routine every 15 minutes runs about 100 times a day, and two bots checking a source on a clock spent 15% of a week in half a day.

- Files in `/workspace` survive an update, and installed packages are wiped.
- Deleting a bot leaves its files and sign-ins on the computer.
- Hiding a bot does not pause its routines.
- Routines may pause after a long time away from the app.
- A first task names outcome, sources, limits, deliverable and review point.
- At a login, captcha or payment, the person takes over, then hands back.
- Approval rules are plain words in Settings.
- A review model checks each proposed action.
- "Require approval" beats "always allow".
- A long chat makes that bot's routines cost more, so use a fresh bot.
- Duplicating copies profile, skills and routines, with empty chat and memory.
- Routines report only the unusual.
- A routine on a broad event, like every message, wastes the allowance.
- A test run does real work.
- Caps: fifty bots and group chats per account, fifty routines per bot.
- When it breaks: retry, restart, Recover, Update, then Reset.
- Recover and Update keep files and logins.
- Reset restores the last saved copy.

The product stops and asks before a send, a purchase, a delete, a publish or a production change, and on this desk work between bots passes through files in a repository.
