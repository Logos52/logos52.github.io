# Grok Bot, Condensed

A short set of operating rules kept coming up over the mid-September 2026 public workshop. They are not a catalog of every demo, and they are not a personal desk roster.

Give each helper one named job. Generic assistants blurred together on stage. Named roles with a single duty, from a slides specialist to a bake-and-critique set working on one product, made it clearer who should act.

Put the rules on the helper. Format, cadence, and hard limits belonged in the profile, where they could be inspected, rather than only in a prompt you might forget to paste.

Recurring work is something you ask for in the thread. Memory is supposed to persist across sessions. Once a preference is stored, it should reappear when that sort of choice comes around again.

When a fork appears, name the options. The stage used an explicit trio. You could lock the current direction, keep iterating, or hold. If you lock, say who builds.

Draft before anything leaves the building. A locked markdown spec went to engineering before side effects. A form helper built an artifact and was marked as not sending it. The same discipline showed up as an approval gate before a message could be posted outside the thread.

Default external writes and destructive infrastructure changes to a hold. One day showed approve-or-hold on territory-style decisions. Another showed a deliberate hold that left a web filter untouched rather than flipping it.

Answer from what is public. Use internal policy only to decide, and do not paste it out. When confidence is low or the request is ambiguous, hand the question back rather than inventing a reply.

If a connector fails, say that it failed. A missing page stopped a critique helper mid-demo. Inventing the missing page would have been the worse move.

Scope the job the way you would write a job description before you let a helper run freely. Bloated context was called out as a thing that slows the work.

Keep fleet health visible. A running overlay of how many helpers exist, how many are working, and how many actions are in flight was part of the demonstration, not an afterthought.

This list is the short form. What the product is sits on the primer. How to run those rules day to day sits on the usage page. What happened on each workshop day sits on the event chronicle.
