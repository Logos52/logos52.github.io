# Picking a computer

Four products can all look like an agent working while you sleep. Grok Bot keeps a shared cloud desktop for standing watch. Cursor Cloud Agents clone a repo on an isolated machine and open a pull request. pstack is a plugin that forbids calling a UI job done without a picture. Grok Build and Cursor Agent mode still need this Mac, or you in the files. If the next job goes to the wrong one, you either stay the clock, share a login, skip the screenshot, or get two writers on one tree.

This page is the map. It does not add a seat. It does not restaff from the September 2026 livestream. It does not install pstack. The dated roster is [[wiki/Systems/AI & Agentic Systems/Current Agentic LLM Stack|Current Agentic LLM Stack]]. The livestream findings are [[wiki/Systems/AI & Agentic Systems/Grok Bot Galaxy|Grok Bot Galaxy]].

This desk should pick one computer per job, using the table below. This desk should not invent a fifth product to sit in the middle.

## Core takeaways

- Standing watch on public material → Grok Bot. Overnight specified code on a non-wiki repo → Cursor Cloud Agent. Sitting in the files → Cursor. Files on this Mac that you will finish before the lid closes → Grok Build. Wiki prose → Grok Build calling Grok 4.6, never a Bot.
- A Grok Bot may start a Cloud Agent. That Bot is a coordinator. You merge. The Bot never writes `wiki/`.
- pstack is a ban, not a computer. Use the ban on a clickable reader. Install the plugin only after an agent can already drive that reader without you.
- The September 2026 livestream showed the same four objects at company scale. Take named roles, Lock / Iterate / Hold, draft-only outbound, Bot-as-coordinator. Do not copy a twenty-helper overlay or auto-merge.
- One writer per tree. Two local agents on one checkout failed on 12 June 2026. Two Cloud Agents on two VMs are not that failure. A Cloud Agent and a local agent on the same branch are.

## Whether this desk should

Use this page when the next job could go to more than one product. Skip this page when the job is already named on the stack table (wiki prose, tan on disk, standing packet). Do not use this page as a reason to create helpers, install plugins, or spend past the Cursor subscription.

## Which computer

| The job | The computer | Why that one | Not that one |
|---|---|---|---|
| Standing watch, fetch, file, public material | Grok Bot | The desktop keeps running after the lid closes | Private logins; wiki; dictionary JSON |
| Overnight or parallel code, fully specified, pull request as handoff | Cursor Cloud Agent | Isolated VM, clone from git, artifacts on the PR | Wiki; a task that still needs your screen; a second writer on a live local branch |
| Sit in the files, Tab, diffs, debugger | Cursor Agent mode | You are at the keyboard | Overnight work; standing watch |
| Finish on this Mac before the lid closes | Grok Build | Real files and toolchain, isolated profiles | A duty that must survive the closed lid |
| Wiki, journal, decision, report | Grok Build calling Grok 4.6 | The writer seat | Grok Bot; Cloud Agents |
| Clickable reader must prove a visual change | Same computer that is writing the reader, plus the pstack ban | Done means a picture | Tests-passed-only; installing pstack as a personality |

## How they compose

A standing helper notices a public bug report. It restates the bug in plain English. If the fix is application code, the helper starts a Cloud Agent and stops. The Cloud Agent clones, edits, drives the app if a verification skill exists, and opens a pull request with pictures. You read the pictures and merge. That is the loop the livestream called engineering. This desk already had the loop as seats. The livestream did not invent it.

pstack sits inside the Cloud Agent run or the local Cursor run. It is not a fourth computer. If the harvest reader cannot be opened, clicked, and screenshotted without you, you need that script before any plugin.

Grok Build stays on this Mac for wiki and for jobs you will finish while you are here. Cursor Agent mode stays for the hour you are in the files. Neither is overnight.

## What the livestream added, and what it did not

Named roles and never-do lines in the helper description. Lock / Iterate / Hold on a fork. Draft-only outbound. Bot starts the Cloud Agent. One finder, finding as a spec. Those change what you type in helpers you already have.

A chief of staff on mail. Auto-merge from CI. One computer per helper. Twenty-plus helpers as a roster. Store logins, refunds, ads spend. Those stay refused. The FAQ still says one computer per user, not per Bot.

pstack's `/poteto-mode` on a public pull request is the ban in public. It is not an install order.

## The case against, the cost, and when to quit

The case for a map is that four names now sit in the same week of notes and will keep colliding. The case against is a fifth page that restates the stack. If this page is opened more than the stack table, the stack table failed. If this page is never opened, the collision was imaginary.

The cost is attention. Each extra product in the window is a chance to pick the shared Bot computer for a diff, or a Cloud Agent for a wiki sentence.

Quit using this page as a catalog. Quit adding a helper because a livestream overlay counted twenty-nine. Quit starting a Cloud Agent for a job Grok Build would finish before dinner. Quit installing pstack to feel like the loop is complete.

Checkable expectation: the next real job names one computer in the first message, and the other three stay closed. If you opened two, the map did not hold.

## How to practice this

1. Take the next job and say which row of the table it is before you open an app. Notice if you still want two computers.
2. If it is standing and public, open Grok Bot only. If it is overnight code, open a Cloud Agent only. If it is wiki, open Grok Build only.
3. On a visual reader change, require a picture no matter which computer wrote the diff.
4. After a livestream clip, write one never-do line into an existing helper, or write nothing. Notice that "create a new helper" was the wrong close.

If the next job still needed a question about which app, the map failed. If you opened one computer, it worked.
