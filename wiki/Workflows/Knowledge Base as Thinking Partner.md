# Knowledge Base as Thinking Partner

A knowledge base used as a thinking partner does two jobs: it helps decide what to think about next, and it holds what has already been learned. Every page and every session faces one test, which is whether the page made the next action clearer. When the answer is no, the system is turning into storage.

Each session should leave at least one useful output and end with a write-back, meaning the result is written into the smallest useful place, because a session without one was only browsing. The most useful material is usually the tension between two pages, and one session with a live question, a few related pages and one write-back is enough to repair a passive system.

## An archive and a thinking partner

An archive stores finished material, while a thinking partner changes the next move. A page is a surface to think on, so the work does not end when the page is written.

The kinds of help a partner gives are pattern-finding, gap-finding, frame-testing, question-generation, and turning a vague interest into concrete work.

Every interaction should leave at least one of five outputs: a sharper question, a better frame, a visible gap, a next action, or a reusable synthesis. A session that produces none of these retrieved well and still failed the test.

The mechanism has two steps: first the current mental model is written down, and then related pages are used to test it. A system that only retrieves is an archive with a better search function.

The loop is:

```text
interest → question → relevant pages → pattern or contradiction → synthesis → next action → updated page
```

The last arrow, the write-back, is the one that cannot be skipped.

The knowledge base compounds when old pages start changing how new problems are approached. Adding sources alone does not compound it.

| Archive asks | Partner asks |
|---|---|
| Where should this go | What does this change |
| What did this source say | What can I do differently now |
| What pages exist | What pages should talk to each other |
| What do I know | What am I missing |

Archive mode is still useful because it keeps the system legible, but thinking-partner mode is the one that changes the next move.

## The five moves

### 1. Start from an active pressure, not a random topic

The system serves current judgment as well as later lookup. To find that pressure, ask what is being decided, where the work is stuck, what keeps recurring, what feels important but under-formed, and what would make this easier to act on.

### 2. Pull nearby pages, and do not start from scratch

The graph, the index, the backlinks and the obvious links are enough to find them.

### 3. Work the tension between pages

The useful material is usually the tension between pages rather than anything in a single page. Six kinds of tension are worth looking for:

- a concept with no operating model,
- two pages that imply different actions,
- a repeated failure mode,
- a missing link between theory and practice,
- a technique that does not change behavior,
- an interest with no next action.

### 4. Convert the insight into a handle

A handle is a short name, question, or rule that can be used again later when the situation returns. It can be a title, a question, a checklist, a contrast, a next exercise, a decision rule, a page split, or a journal prompt. The handle is what makes the idea reusable, because a good one is easy to find again at the moment it matters.

Worked conversions:

- "better study habits" → Prestudy, [[wiki/Dimensions/Deep Processing/Bear Hunter System|Bear Hunter System]], [[wiki/Dimensions/Retrieval/Spaced Interleaved Retrieval|Spaced Interleaved Retrieval]]
- "too many interests" → [[wiki/Razors|Balancing Multiple Interests: Breadth v Focus]], [[wiki/Self Management/Priority 0+1 System|Priority 0+1]]
- "consuming without changing" → [[wiki/Razors|Are You Thinking, or Just Consuming?]]
- "method looks right but nothing improves" → [[wiki/Dimensions/Self-Regulation|The Technique Is Only as Good as the Thinking It Produces]]

### 5. File the result into the smallest useful destination

Write-back is one of the five moves and it is required.

| Kind of result | Destination |
|---|---|
| Passing thought | [[journal/index\|Journal]] |
| Active question | Journal, What's On My Mind |
| Current working area | Journal, Current Focus |
| Durable operating model | wiki |
| Personal plan | private Goals or Skills |
| Public argument | blog draft |
| System change | README, AGENTS, or a workflow page |

A new page is worth creating only when it will be reused, linked, practiced, or argued with.

## What it looks like when it is working

The important threads are already written down when the work is picked up again. Old pages are changing how new problems get approached. A session that produced no write-back failed the test, however much was read. A vault can also turn into a feed, by the mechanism set out in [[wiki/Self Management/Flow State|Social Media - Curvilinear Design & the Theft of Time]].

## One session, when the system feels passive

One session is enough, because the goal is to make one part of the vault more usable, and processing all of it is unnecessary. A session costs one live question, three to six related pages and one write-back.

## Failures and their repairs

| Failure | Repair |
|---|---|
| Knowledge hoarding | Ask what the page changes |
| Index addiction | Start from a live problem |
| Link decoration | Link only when the relationship matters |
| Permanent synthesis | Use [[journal/index\|Journal]] for temporary thinking |
| Private/public confusion | Keep private Goals, Skills, and Kolbs local unless they are intentionally publishable |
| Agent overproduction | Ask for operating model, causal chain, failure modes, practical feel, and implications |
| Archive drift | End each session with a question or an action |

A Kolbs note (a review modelled on Kolb's experiential cycle) records, after an attempt, what happened, how it felt and why, what rule that implies, and what changes next time.

## Good signs and warning signs

The system is working when:

- the next question is obvious,
- old pages explain new problems,
- titles have become handles,
- interests are alive but bounded,
- the Journal reflects current attention,
- the index is stable enough,
- outputs are shorter because context is already held.

The system is drifting when:

- every session starts from zero,
- pages are polished but unused,
- the graph is interesting but not actionable,
- new sources do not update old pages,
- Journal questions sit unchanged for weeks,
- the system looks impressive and nothing changes because of it.

## The weekly questions

The weekly review asks five questions once, and it exists to produce a next action.

1. What page changed how the week was acted?
2. What question kept returning?
3. What thread is stale?
4. What should be synthesized next?
5. What belongs in a blog post?

## What a session costs, and when to stop

An agent that keeps producing pages with no live question behind them is overproducing. The fix is to ask it for the operating model, the chain of causes, the failure modes, the practical feel and the implications.

Quit signals: two sessions that start from zero, a week of Journal questions unchanged, or a weekly review that produces no next action.

## How to practice this

1. Pick one live question from work in progress. Ask what is being decided, where the work is stuck, or what keeps recurring. Notice whether a real pressure exists or the topic is random.
2. Read three to six related pages found through the graph, index, backlinks, and obvious links. Notice that three to six is a house limit, not a finding.
3. Write your current answer to the question in plain language. Notice which of the pages then contradict what you wrote.
4. Name the tension between the pages. Notice that the tension is usually more useful than a single page.
5. Convert the result into a handle: a short name, a question, or a rule. Notice whether you could use it again when the situation returns.
6. Pick a destination and add one link, one next action, or one open question. Notice whether the next action is clearer than it was before.
