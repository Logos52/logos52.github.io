# The Shortcut Problem

The shortcut problem is a finished note, highlight, map, or answered prompt standing in for the evaluation, comparison, or reconstruction the task needed. The swap usually feels productive, because easy processing is taken as evidence of learning.

Learning techniques exist to produce a specific kind of thinking. The shortcut problem is a technique carried out without that thinking.

## Core takeaways

- A finished artifact can replace the thinking it was meant to force. The session then ends with the object and without the learning.
- The swap feels productive because easy processing is read as knowledge. The gap shows on the next test.
- The clearest sign is a page of notes that looks ordered and cannot be used.
- Every shortcut has the same shape: a visible move that gets finished, and an act of thinking that gets skipped.
- Bear Hunter System and Spaced Interleaved Retrieval can both be faked by doing their steps as surface actions.
- Six questions asked during the session catch the swap. The repair is one small, named change aimed at the shortcut.

## How the swap happens

When the work gets uncertain, effortful, or uncomfortable, the learner looks for a simpler path. Simplifying is fine when the important thinking still happens. The problem is simplifying that removes the thinking.

The pattern has five steps. The task needs evaluation, comparison, or reconstruction. The learner feels the load. The learner looks for a cheaper path. A visible study behavior gets finished. The artifact looks right, but the knowledge did not move enough.

This is one reason a method can look correct while results stay flat. The thinking skipped in the session is still missing in later sessions. During the session, easy processing is counted as mastery, so the session feels like it worked. The next test then shows what was not learned.

[[wiki/Syntheses/Are You Learning, or Just Using Techniques|Are You Learning, or Just Using Techniques]] is a related diagnosis of the same failure.

[[wiki/Syntheses/Are You Learning, or Just Using Techniques|First Principles of Learning]] keeps meta-strategies for overwhelm because this swap is how overwhelm turns into busywork.

## The eight shortcuts

| Visible move | Thinking it skipped |
|---|---|
| Transcribing someone else's explanation | Inventing and checking a structure of your own |
| Marking a line | Asking why that line earns its place |
| Putting an arrow between two nodes | Stating the relation the arrow claims |
| Asking a language model for the outline before a first pass | Doing the first organization |
| Polishing a map | Ranking relations and sitting with the confusion |
| Going over the text again | Reconstructing from a closed book |
| Reciting details | Building a schema those details can hang on |
| Changing methods | Staying long enough for the method to train the skill |

Every row has the same shape. The left column is the finished object. The right column is the cognition the object was supposed to force. The session produced the object without the cognition.

## How to tell it is happening

The clearest sign is a page of notes that looks ordered and cannot be used. The feeling of productivity during the session is a misreading of fluency. Easy processing is being taken as evidence that the knowledge is there. The check has to happen during the session. After the session is too late.

[[wiki/Concepts/The Technique Is Only as Good as the Thinking It Produces|The Technique Is Only as Good as the Thinking It Produces]] states the same idea as a rule for choosing a method: pick a method for the cognition it triggers.

## Faking the Bear Hunter System

Bear Hunter System is four-pass encoding: a rough frame, questions the material must answer, a working map of connections, then a cut-down structure that survives without the source. The shortcut happens when the steps become surface actions.

| Pass | Surface fake | Repair |
|---|---|---|
| Aim | Listing topics | Write what, why, and how the material must answer before it is opened |
| Shoot | Filling the map with source explanations | Use the source to answer the Aim questions |
| Skin | Making the map neat | Cut to what can be rebuilt with the source closed |

What matters is whether the map made the learner decide what was important, how pieces relate, and how they group. A clean map that never made those decisions is the arrow row and the polish row from the eight shortcuts, done inside a method.

[[wiki/Dimensions/Deep Processing/Bear Hunter System|Bear Hunter System]] is the method.

[[wiki/Dimensions/Deep Processing/Aim|Aim]] is the first pass: listing topics is the shortcut; writing what, why, and how is the repair.

[[wiki/Dimensions/Deep Processing/Shoot|Shoot]] is the second pass: filling the map with source explanations is the shortcut.

[[wiki/Dimensions/Deep Processing/Skin|Skin]] is the third pass: making the map neat is the shortcut.

[[wiki/Dimensions/Deep Processing/Importance-Based Chunking|Chunking as a Technique]] is the real work a clean map is supposed to have done.

## Faking Spaced Interleaved Retrieval

Spaced Interleaved Retrieval is retrieval spread over time and mixed across topics and forms. It can be faked five ways.

| Fake | What it avoids |
|---|---|
| Peeking at notes too soon | Reconstructing with the source closed |
| Recognizing a line instead of rebuilding it | Recall rather than familiarity |
| Repeating the same prompt until it feels familiar | A new angle on the same knowledge |
| Staying inside one topic to avoid the mix | The discomfort of interleaving |
| Treating a gap as failure | Using the gap as information |

Good retrieval should show whether knowledge can be rebuilt, compared, explained, and applied. A queue that only confirms recognition has been faked.

[[wiki/Dimensions/Retrieval/Spaced Interleaved Retrieval|Spaced Interleaved Retrieval]] is the method. Look-up, recognition, and blocked practice are the fakes that replace it.

## Catching it during the session

Six questions to ask during the session:

- Is there an artifact I cannot explain?
- Did I take the easiest version of the task?
- Did I steer around uncertainty?
- Can I state the relationships, not just name the nodes?
- Can I rebuild it with the source closed?
- Did the method make me think harder, or look busy?

Set up the work so the swap is harder to make. Require a reason for every connection. Ask why a piece matters before adding detail. Compare similar ideas before summarizing. Dump from memory before checking notes. Mix topics.

## Fixing it after the session

After an attempt, name what just happened, how it felt and why, what rule that suggests, and what changes next time. This gives the shortcut that just fired a name.

[[wiki/Dimensions/Self-Management/Kolbs Experiential Cycle|Kolbs Experiential Cycle]] is that after-the-fact naming.

Pick one small, named change aimed at the shortcut itself. Do not build a new system.

[[wiki/Dimensions/Mindset/Marginal Gains|marginal gain]] is that change.

Some shortcuts are old cue-response habits. The cue is overwhelm. The response is copying, asking a model, rote repetition, or leaving. Repairing a habit is a different job from catching a one-off.

[[wiki/Concepts/How to Unlearn Old or Bad Habits Efficiently|How to Unlearn Old or Bad Habits Efficiently]] covers the habit repair.

Catching the swap while it happens is a noticing skill.

[[wiki/Dimensions/Self-Regulation/Metacognition - The Control Layer|Building the Radar]] is that skill.

The aim is to stop replacing learning with the appearance of learning. The artifact can stay, as long as the thinking it was supposed to force happens with it.

## How to practice this

1. During a session, look for an artifact you cannot explain. If you find one, the artifact replaced the thinking.
2. Close the source and rebuild the material from memory before you check your notes. Notice whether you recall it or only recognize it.
3. Before you draw an arrow between two nodes, state the relation the arrow claims. Notice how many arrows you cannot state.
4. Mix topics in your retrieval instead of staying inside one. Notice whether you avoid the mix to stay comfortable.
5. After an attempt, write what happened, how it felt and why, what rule that suggests, and what changes next time. Notice which shortcut fired.
6. Pick one small change aimed at that shortcut. Do not build a new system. Notice whether the same shortcut fires again next time.
