# Metacognition - The Control Layer

> Self-regulation depends on seeing what your mind is doing while learning runs. Metacognition is that control layer: a cue appears (often a feeling before a thought), you monitor it instead of letting it pass, then you respond, usually by refusing the shallow shortcut and staying with the thinking the method was meant to force.

## The cue–monitor–respond loop

Feelings arrive faster than articulated thoughts. Effort, difficulty, confusion, overwhelm, and even promising ease are cues. Passive rereading feels smooth because almost nothing is asked; deep work feels heavier because more is asked.

**Monitoring** is the radar: did the cue register, or did an old habit already act? On the productive path, discomfort often means an old habit was interrupted, not a signal to quit. Once you can catch drift repeatedly, skill-building accelerates because you can return to the path that actually builds memory.

[[wiki/Concepts/The Shortcut Problem|The Shortcut Problem]] is what happens when the response chooses the finished artifact over the cognition. [[wiki/Dimensions/Self-Regulation|Self-Regulation]] covers traps, measurement, and energy around this loop.

## Competence and what counts as progress

Skill moves through unconscious incompetence, conscious incompetence, conscious competence, and automatic competence. Outcomes like retention lag early skill work. Noticing shortcuts you took for three weeks **is** progress if naming them enables repair.

Judging only by final scores makes complex skills look like failure for a long time. Metacognition shifts the scoreboard toward whether you caught the failure mode.

## Prediction error

A second loop sharpens the first: before an attempt, state a **narrow prediction** of what will happen; run the attempt; compare feedback to the prediction. The gap is **prediction error**, the signal that your current model needs updating. Skipping prediction blurs which adjustment mattered; waiting weeks for external feedback blurs causality.

Guided questions force the prediction into the open: one small change, one experiment, deliberate search for error once basics are in place. Pair with [[wiki/Dimensions/Self-Management/Kolbs Experiential Cycle|Kolb’s cycle]] for after-action naming.

## Inside techniques

Methods fail when their cognitive step is bypassed (listing “why important” without testing the answer, accepting model outlines before a first pass, understanding an explanation without saying how it changes what you already know). Difficulty helps when aimed at relational work, not confusion for its own sake.

The [[wiki/Dimensions/Self-Regulation|self-regulation hub]] states the rule in one line: a technique is only as good as the thinking it produces.

## Building the radar in session

Useful monitoring is lightweight, not a second full task. A few habits train it:

- When effort spikes, **name the feeling** before choosing the next action (confused, rushing, seeking relief).
- When you reach for a tool or shortcut, ask whether it replaces thinking you have not done yet.
- Before closing a block, state one thing you could not rebuild without the source. If nothing qualifies, the block may have been shallow.
- After feedback (quiz, problem set, tutor comment), write what you expected versus what happened; one sentence is enough to preserve prediction error.

Early on, the loop feels slow. The payoff is cumulative: each caught shortcut is cheaper than the exam that would have exposed it.
