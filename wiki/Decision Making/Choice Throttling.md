# Choice Throttling

Choice throttling is a short chain of closed questions. Each question has a yes or no answer, or another small fixed set of answers. Each answer removes some of the options. The chain is a substitute for rumination. It is not a way to force a pick from a pile of options by willpower.

## Core takeaways

- The method is a chain of closed questions, answered in order, where each answer removes options.
- It fits decisions of low to medium complexity, where the trouble is too many floating variables. It is not enough for the heaviest choices.
- The right starting questions ask about consequence, reversibility, the value of waiting, the main downside, and the current goal. "What should I do?" is the wrong start.
- A question about values can take months to answer. That is still progress, because the missing information now has a name.
- Stop when the next answer would not change the choice, or when a whole branch is already rejected on principle.

## How to run the chain

Use the method when the set of options has to shrink before judgment can work on it. Name the variables that are creating the uncertainty. Turn each variable into a yes/no question or another closed question. Answer the questions in order. Each answer removes part of the option set. The result is a dichotomous key, an ordinary tool of operations research.

The method replaces open-ended rumination with a fixed path through the decision. It is meant for low-to-medium complexity, where the main problem is too many floating variables and not a lack of values. For the heaviest choices this is not enough. Local uses that fit: choosing between study methods, deciding on an optional event, picking a task for a work block, deciding whether to continue or switch, and narrowing tools, resources, or plans. For a very simple decision, a faster filter can be enough: if the answer is not a clear yes or a clear no, the decision may not matter much.

## Which questions to ask

The bad version is "What should I do?" Better starting questions: Is this choice high consequence? Is the decision reversible? Will waiting produce useful information? Does this protect the main downside? Does this align with the current goal? Each question should reduce the decision space. Cut whole branches that will not be taken on principle. Once a category is rejected, stop evaluating the options inside it.

An open question leaves all the options in place, so the set stays large. A closed question removes some options each time it is answered. Some yes/no questions take a long time to answer, especially questions about values. That is still progress, because the missing information now has a name. A values question can take months and still be the right question to ask. A simpler question does not always get a faster answer.

## Ways the chain fails

Each failure has a fix.

- Fake binary: the question is yes/no but the variable has degrees. Rewrite the question, or add thresholds.
- Wrong variable: the answer does not change the decision. Ask which uncertainty actually controls the choice.
- Too many questions: the chain itself has become overthinking. Keep only the variables that change the decision. A long chain that never removes an option is rumination.
- Values unclear: every option looks equivalent. Do reflection or a values check first, or work through [[wiki/Dimensions/Self-Management/Kolbs Experiential Cycle|Kolbs Experiential Cycle]] first.
- Complexity mismatch: the decision is too heavy for this method. Move to a heavier process on the [[wiki/Decision Making/Decision Making|Decision Making]] hub.

## When to stop

Stop when the next answer would not change the choice. Stop also when a whole branch is already rejected on principle. A stop condition is part of the method, in the same way a starting question is. The heaviest choices still need a heavier process.

## How to practice this

1. Pick a decision of low to medium complexity, such as which task to do in a work block. Notice whether the trouble is too many floating variables or unclear values. If values are unclear, the method is the wrong tool.
2. Write down the variables that make the decision uncertain. Turn each one into a yes/no question. Notice any question where the variable has degrees. Rewrite that question, or add a threshold.
3. Answer the questions in order, starting with consequence, reversibility, and whether waiting brings useful information. Notice how many options each answer removes.
4. When an answer rejects a whole category, stop evaluating the options inside it. Notice whether you keep drifting back into the rejected branch.
5. Stop when the next answer would not change the choice. Notice if the chain has grown long without removing options. A long chain that removes nothing is rumination. Cut it down to the variables that change the decision.
